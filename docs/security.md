# Security and privacy

## Protected data

Jiwoo treats mood, energy, tags, and journal text as sensitive. These fields are encoded into one JSON payload and encrypted before they reach SQLite.

## Cryptography

- Algorithm: AES in Galois/Counter Mode with a 128-bit authentication tag.
- Key: generated by Android Keystore under the alias `jiwoo-journal-v1`.
- Nonce: a fresh provider-generated IV for every encryption operation.
- Envelope: IV length, IV, and ciphertext encoded as Base64.
- Stored metadata: record identifier plus creation and update timestamps.

GCM detects ciphertext modification during decryption. The key is never exported by application code.

## Data movement

- The manifest declares no internet permission.
- There is no analytics, advertising, cloud, or account SDK.
- Cloud backup and device-transfer extraction are disabled.
- Reminder notifications contain a generic prompt rather than journal text.

## Tested control

The instrumentation journey saves a known sentence, queries every `encrypted_payload` row in the actual SQLite database, and fails if that plaintext is present.

## Threat model limits

Jiwoo protects journal content at rest against casual database access and copied database files. It does not claim to protect an unlocked device from its owner, a compromised operating system, screen capture by privileged software, or physical forensic recovery. Biometric app locking and encrypted export are future designs, not current claims.

## Reporting

Please use the private vulnerability reporting process described in [`SECURITY.md`](../SECURITY.md). Do not include real journal content in a report.
